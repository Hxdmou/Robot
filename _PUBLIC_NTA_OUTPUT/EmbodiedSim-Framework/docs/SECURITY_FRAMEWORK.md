# 企业级安全防护框架说明

## 1. 安全设计总览

本框架为具身智能系统提供 **5 层纵深防护 + 审计 + 熔断** 的企业级安全保障：

```
             入站动作指令
                  │
                  ▼
    ┌─────────────────────────────┐
    │ Layer 1: 输入合法性校验       │  类型/范围/NaN-Inf/数量 校验
    └──────────────┬──────────────┘
                   ▼
    ┌─────────────────────────────┐
    │ Layer 2: 关节限位+工作空间围栏 │  硬限位裁剪 / 软限位告警
    └──────────────┬──────────────┘
                   ▼
    ┌─────────────────────────────┐
    │ Layer 3: 速度/加速度限制     │  防止关节速度过大造成冲击
    └──────────────┬──────────────┘
                   ▼
    ┌─────────────────────────────┐
    │ Layer 4: 碰撞检测接口         │  仿真/力矩/皮肤/视觉 多源融合
    └──────────────┬──────────────┘
                   ▼
    ┌─────────────────────────────┐
    │ Layer 5: 命令限流熔断器       │  >2000条/s 判定为指令风暴并熔断
    └──────────────┬──────────────┘
                   ▼
           ┌──────┴───────┐
           │  紧急停止开关  │ ← GUI按钮 / Enter键 / 程序调用 / 硬件IO
           └──────┬───────┘
                  ▼
       （允许/拒绝 + 安全事件审计日志）
```

## 2. 各层实现细节（engineering/safety_controller.py）

### Layer 1: 输入合法性

| 校验项 | 命中行为 |
|--------|---------|
| 指令不是 list/tuple | CRITICAL → 熔断器触发 |
| 关节数量和机器人关节数不匹配 | CRITICAL → 熔断器触发 |
| 某个关节值含 NaN / Inf / 非数值类型 | CRITICAL → 熔断器触发 |

### Layer 2: 关节限位与工作空间围栏

- 硬限位：超出 `±2°` 裕度即 CRITICAL；
- 软限位：进入裕度区间仅 WARN，同时自动把关节值裁剪到合法区间继续运行（工程常用降级策略）；
- 工作空间围栏：默认笛卡尔区间 `x∈[-0.5,1.2], y∈[-0.8,0.8], z∈[-0.1,1.5]`（米），
  可通过 `SafetyController(cartesian_workspace=...)` 传入真实场景值。

### Layer 3: 速度限制

- 基于 `time.time()` 的实际时间差计算瞬时速度，
- 默认单关节速度限制 2.0 rad/s，构造参数 `velocity_limit_rad_s` 可调。

### Layer 4: 碰撞检测接口

`CollisionDetector` 是抽象基类，常见对接方式：

| 实现方式 | 对接点 | 触发条件 |
|---------|--------|---------|
| 几何距离检测 | PyBullet `getClosestPoints` | 最近点距离 ≤ 阈值（默认5cm） |
| 力矩残差检测 | 关节力矩读数 - 模型期望力矩 | 残差超过阈值（由用户注入） |
| 电子皮肤 | 触觉传感器总线读数 | 任一触点力超过阈值 |
| 3D视觉入侵检测 | 工作空间深度点云 | 禁区内出现人体轮廓 |

公共示例默认提供 `MockCollisionDetector`，可调用 `set_simulated_distance(0.03)` 模拟近距离场景用于调试安全流程。

### Layer 5: 命令限流熔断器

- 1 秒滑动窗口计数，默认限流 **2000 条/秒**；
- 超过即判定为「指令风暴」（常见于上位机逻辑异常或被攻击）；
- 熔断后所有动作指令被拒绝，必须人工 `reset_fuses()` 才恢复。

## 3. 紧急停止 & 熔断器

### 触发路径（多路并联）

| 触发源 | 如何触发 |
|--------|---------|
| GUI 红色大按钮 | 鼠标点击 / `Return` 键 |
| 程序 API | `SafetyController.trigger_emergency_stop(reason=...)` |
| 碰撞检测层 | 距离 ≤ 阈值 自动触发 |
| AI 决策层 | 技能库中的 `safety_stop` 工具 |
| 真实硬件 IO | 接入硬件急停通道后，由 GPIO 回调触发（对接示例） |

### 复位步骤

1. 确认现场已无安全风险；
2. GUI中按 `Ctrl+R` 或调用 `SafetyController.reset_fuses()`；
3. 观察系统状态输出 `system_ok` 变为 `True`；
4. 先用小幅度/低速动作重新验证运动正确性。

## 4. 安全事件审计

所有安全事件都通过 `on_safety_event(callback)` 机制推送给订阅者，建议在工程化部署时至少实现：

- ✅ **控制台彩色打印**（开发调试用）
- ✅ **结构化日志落盘**（DataRecorder 记录到 CSV/JSONL）
- ✅ **异常严重级消息推送到报警系统**（企业微信/钉钉/短信网关）
- ✅ **安全事件写入时序数据库**（InfluxDB / Prometheus + Grafana 仪表盘）

安全事件数据类字段：
| 字段 | 内容 |
|------|------|
| `event_type` | 枚举值（见 SafetyEventType） |
| `severity` | INFO / WARN / CRITICAL |
| `source` | 触发模块名（便于定位） |
| `message` | 人类可读原因（含数值） |
| `timestamp_s` | 精确到微秒时间戳 |
| `extra` | 扩展字典（如当前坐标/距离/速度） |

## 5. 防御 AI 诈骗与恶意指令的工程建议（非代码安全）

结合项目定位，建议在「人机协同」场景下额外叠加 3 道防御：

| 层级 | 措施 |
|------|------|
| **指令来源白名单** | 仅允许指定上位机 IP / 已签名的指令包进入安全控制器 |
| **任务审批闸门** | 对「大负载 / 高速度 / 人员附近」类任务，先在孪生系统预演通过再发真机 |
| **语义一致性校验** | 高层任务描述 → LLM 解释技能意图 → 由安全策略层比对是否越权（例如用户说「拿杯子」被AI理解成「扔杯子」时被拦截） |
